What Makes This Hard

  • Sub-millimeter placement accuracy - thousands of cycles without drift
  • Every pick from a tape feeder lands slightly differently
  • Thermal drift: machine warms -> mechanical tolerances shift -> recalibration required
  • Speed and accuracy oppose each other - faster moves increase settle error
  • Step loss is silent - all placements uniformly offset

The Full Pipeline

  • Stenciling - solder paste through a laser-cut stencil
  • Pick and place - every SMT component placed by the machine
  • Reflow - controlled heating profile

V1 - Production & Root Cause

V1 in operation

What V1 Delivered

  • Production unblocked - ~40 display boards; controllers hand-soldered in parallel
  • Board overage built - bought runway for V2
  • ~25% LED failure rate -> near-zero by owning the reflow stage

Why It Couldn't Scale

  • Cartesian: Y motors carried the entire X gantry (~2kg+) - high inertia
  • Open-loop: step loss undetected in real time - placements uniformly offset
  • Step loss worsened as motors heated
  • Reducing speed bought reliability but killed throughput
  • Required two fixes: closed-loop drives + lighter machine architecture

V2 - What Changed & Why

V2 production run

Problem -> Solution

  • Heavy Cartesian Y-axis gantry -> CoreXY
  • Open-loop step loss -> closed-loop XY drives (CL42T + integrated encoder)
  • Solid heavy X-axis -> LDO Voron-spec skeletonized aluminum rail
  • Aluminum Extrusion V-Rails -> Linear Rails
  • Large metal end-effector -> CF/ASA Z/R mount
  • Multiple cable runs -> single MTP USB 2.0 (24V + data)
  • No optics -> dual-camera vision pipeline with per-pick correction
  • Custom 3D printed stepper feeder -> Yamaha pneumatic feeders

V2 - CoreXY Architecture

V2 XY motion speed test

Why CoreXY Changes the Dynamics

  • Both motors fixed to the frame - zero moving motor mass; only the lightweight carriage moves
  • A = X+Y, B = X-Y - both motors engage on every move
  • Y-axis motion is the dominant axis on this machine; in a Cartesian one motor drives it alone
  • With CoreXY both motors drive it simultaneously, doubling available torque on the primary axis
  • Lower inertia + full dual-motor torque -> significantly higher achievable acceleration
A motor: X + Y (diagonal belt path)
B motor: X - Y (diagonal belt path)
Work area: 270 x 415 mm (firmware) / 267 x 419 mm (OpenPNP soft limits)
XY step resolution: 160 steps/mm (1/32 microstep) = 0.00625 mm/step
Firmware accel (A/B): 20 m/s² configured; 20 m/s² max
Max speed: 800 mm/s validated; 1000 mm/s firmware limit

V2 - Closed-Loop Drive Selection

OMC TP-series motor + CL42T closed-loop driver

Why CL42T Closed-Loop Stepper

  • NEMA 17 form factor - mechanical drop-in for V1 steppers
  • Integrated encoder: position loop closed at the driver, not in firmware
  • AetherControl still issues step/dir commands; driver handles correction internally
  • Simpler integration than a full servo - no outer position loop in firmware required

Why Maximum Voltage

  • Higher bus voltage -> faster coil current rise per step pulse
  • Faster rise -> higher step rates before back-EMF limits torque

V2 - RS232 Driver Tuning

Driver Defaults Not Stable

  • Default CL42T parameters left the system unstable under real production load
  • Manual RS232 configuration via MotionStudio over several days of iteration
  • Physical current knob set to 0 - required to unlock software parameter override

Tuning Process

  • Peak Current, Position/Velocity Gain
  • Primary failure mode: fault trips when pushing peak acceleration
  • Following-error window widened to accommodate acceleration transients without false fault trips
  • No oscillation - gains tuned for stability before pushing speed
  • Result: stable production with no step-loss events at full operating speed

V2 - Mechanical: Mass Reduction

Skeletonized X-axis + CF/ASA end-effector mount

Why Mass Matters

  • F = ma - lower moving mass -> higher acceleration for the same motor torque
  • In CoreXY, X-axis carriage mass is coupled to both motors on every move
  • Lower inertia -> faster settle after deceleration -> higher placement rate

Changes Made

  • X-axis: solid extrusion -> LDO Voron-spec skeletonized aluminum rail
  • End-effector motors: NEMA 17 + NEMA 11 -> NEMA 11 + NEMA 14
  • Z/R mount: steel/aluminum -> CF/ASA - stiff, light, heat-stable
  • All structural parts: aluminum where possible

Multi-Controller Integration

Two Independent AetherControl Instances

  • Gantry controller (Teensy 4.1): XY movement + pneumatic feeder actuation + ring light control
  • End-effector submodule (Teensy 4.0): Z pick/place + R nozzle rotation + camera ring light
  • Both registered as separate devices in OpenPNP
  • OpenPNP owns all sequencing - controllers never communicate directly

Async Parallel Operation

  • OpenPNP dispatches to both simultaneously where safe
  • XY gantry move and Z/R can execute in parallel
  • E-stop kills both controllers simultaneously

V2 3D nozzle calibration

Two-Camera Setup + Custom Ring Lights

  • Downward (gantry): fiducial detection, board XY calibration + homing
  • Upward (fixed): part centering + rotation correction before every placement
  • Both cameras: custom WS2812B RGB ring lights

Startup Calibration - Every Run

  • End-effector offset through optical homing
  • Gantry camera to nozzle offset
  • Fixed part camera offset via nozzle position

Full Calibration Procedure

  • 4-pass optical backlash sweep at 5 probing speeds (25%-100% feedrate)
  • 3D nozzle offset calibration: tip X, Y, Z relative to camera axis
X backlash: 0.0331 mm · Y backlash: 0.0211 mm
Backlash methods: DirectionalCompensation (X), DirectionalSneakUp @ 25% (Y)

Placement Accuracy

Target: ≤20% of Pad Dimension

  • Step resolution is the floor: 0.00625 mm (160 steps/mm, 1/32 microstep)
  • Per-pick vision correction compensates for pick variation before every placement
  • R-axis rotation correction - essential for QFN and fine-pitch alignment

  • QFN 0.4mm pitch, 0.2mm pad width - tightest constraint; 10% = 0.04mm tolerance

Lessons Learned

Controls

  • Open-loop is a valid triage choice
  • Driver-level tuning makes the feedback loop stable across operating conditions
  • CoreXY's fixed motors removed an issue that tuning could not fix
  • Calibration - backlash, nozzle offset, thermal drift - is ongoing operations, not a one-time setup

Engineering Process

  • V1 shortcuts were deliberate risk management
  • Building for two systems simultaneously produced firmware that supported research
  • Precision systems demand the full stack: architecture + drives + tuning + calibration + vision

Scope

  • Hardware design (Altium) -> firmware -> software integration -> production operation
  • Custom embedded firmware built to be kinematics-agnostic
  • Async multi-controller coordination with deterministic sequencing
  • Precision calibration pipelines maintained as ongoing operations, not a one-time setup
  • From blocked production to 400+ boards: the machine paid for itself many times over
